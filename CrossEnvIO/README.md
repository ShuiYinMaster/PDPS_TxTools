# CrossEnvIO

在 Process Simulate 工程之间传输模型结构与焊点。资源和零件统一处理，按 SDK 原生类型重建层级；不要求两端具有相同的库目录布局。

## 操作流程

命令：`.跨环境IO→模型结构/焊点`。

1. 在“模型结构 / 焊点”页签选择工作区，在第一栏选择任务、接收进程及传输对象。进程选中后自动读取工程和库目录；场景选取自动捕获模型包。场景选取使用 SDK 原生多选框，文件内容使用独立的只读预览，两者至少保留五行空间。文件重建使用本端工程。
2. 第二栏直接显示本端文件列表和接收库文件夹树，支持多选拖放、按钮分配和同分类批量分配；下方显示目录匹配方式与原生重建坐标框。场景按源层级重建到文档根，不另设接收父容器入口。焊点页直接显示绑定和投影选项。
3. 底部独立操作栏检查并确认执行，第三栏显示问题及 TSV 导出、离线包导出、传输明细、文件清理和日志按钮。问题区域按窗口高度限制并允许滚动，主执行按钮不参与该区域的滚动或内容扩张。单个问题仅显示一份完整说明；多个问题显示简短标题列表和当前选中项的说明。状态栏只表示单行状态，不重复完整错误。检查阶段不复制文件、不修改场景；配置变化会取消此前检查结果。

分配只修改计划，不立即移动文件，默认保留原始 cojt 文件名。同一模型包只复制一份文件，按最终 cojt 路径和实际类型缓存本批次首个可用实例，其余实例通过 SDK 的复制粘贴创建，不重复插入模型。每个独立源对象 ID 对应独立目标实例，保留各自的父级和位姿。复制粘贴只检查目标容器和文档根直接子集来识别新增实例，避免逐个扫描全场景。目录树通过接收端只读接口读取库文件夹，不展示模型包内部或目录联接。目录列表最多读取 5000 项、深度 32 层，无法读取的范围明确提示；可手动指定未显示目录。复杂类型规则、源文件重新定位和同名冲突处理保留在第二栏“高级规则”窗口，单个模型目录覆盖只在主页面分配，导出只保留第三栏入口。

场景选取同时监听 SDK 的拾取、插入、删除、有效名称输入及数据变化事件，并在界面空闲时按工程和选取对象 ID 核对内容。自动识别不进入执行任务互锁，不暂停或重新注册原生拾取，不改变宿主选取；仅暂时禁用执行按钮。事件提前触发或缺失时仍可更新文件列表；仅高亮变化或重复通知不重新捕获。未完成识别的对象保留名称和实际类型；没有可读库引用的对象显示明确状态，不静默隐藏或伪造 cojt 路径。单个已识别文件自动选中，没有有效文件时禁用分配操作。

高级规则窗口可从任务栏恢复，关闭主窗口时一并释放。用户关闭规则窗口只隐藏该窗口；应用退出等其他关闭原因正常处理。文件和目录对话框归属当前可见操作窗口。执行中请求关闭会取消尚在进行的文件复制，并在当前操作结束后关闭主窗口。

源端和接收端参考坐标均使用 SDK 原生坐标框，执行 `接收参考坐标 × 源参考坐标逆矩阵 × 源世界位姿`，同时对齐位置和朝向。源端坐标在调用端选取，接收端为其他进程时在该进程打开原生坐标选取窗口，确认后返回完整坐标；不在源场景冒充接收端拾取。两端默认世界坐标，可一键恢复。自动识别选取内容时不重置坐标控件。焊点和一起携带的模型使用同一变换。焊点绑定问题使用原生多选框确认全部零件，首个零件作为主板。

窗口以 900 × 860 为设计尺寸，可调整大小和最大化；第一栏约占三成，第二栏约占七成，缩窄时上下排列。页面不显示重复的顶部步骤横幅或内容摘要。窗口在屏幕工作区允许的范围内按内容增高，卡片不嵌套滚动条，空间不足时仅滚动工作区外层；问题说明区域保持有界滚动。按钮行由所属布局测量，统一 UI 策略不重复接管行高。原生多选框至少完整显示五行，坐标框使用固定内容行，SDK 初始化重新设定尺寸后仍保持完整可见。接收进程消失或切换时清除过期上下文；刷新同一工程保留有效的目录分配。SDK 原生拾取控件接入统一的焦点和 Esc 退出处理，日志默认折叠。

## 跨库映射

- 分类与 Agent 配方共用 `SRC/SceneObjectTypes.cs`，读取实际 SDK 类型及可用的 Planning、Prototype、Family。默认优先关联源目录后缀及上级分类，再匹配接收目录与资源类型；支持编号前缀及常见中英文目录名称。文件列表显示最终目录，提示文本显示匹配依据。无唯一匹配时要求手动拖放，只有显式配置兜底目录才回退。“同分类”以源目录或明确设备分类分组，不把所有普通组件视为同一分类。显示标签不决定类型枚举范围。
- 同一 cojt 的多个实例只复制一次。共享包命中不同类型目录时必须逐项覆盖；未识别类型没有隐式兜底目录。
- 原始 cojt 路径作为结构关联键；重新定位只改变实际读取位置。目标目录必须位于接收库根以内，拒绝越界路径及目录联接。
- SDK 的 `#\` 路径和普通相对库存储路径按工程库根解析，不依赖进程工作目录。ASCII 联接名按完整路径摘要匹配真实 cojt，或验证持久联接的实际目标，区分中文同名模型的不同版本。重新定位源模型后重新核验包内容，保留原始结构关联并使预检失效。
- 场景集合统一通过 SDK 的 GetDirectDescendants 查询，不把 ITxObjectCollection 强制转换为 .NET IEnumerable。内部几何选取通过原生 Collection 父链归属到组件，并消除父子重复选取。
- 多选导出根重名时，路径使用源对象 ID 区分；`Name` 保留源名称，`TargetName` 记录含源父级和身份后缀的独立目标实例名，防止容器或叶子合并。名称对应关系写入日志及传输明细，预检明确提示。源场景名称及 cojt 文件名保持原样。接收端须声明 `named_roots` 能力，旧端不支持时禁止执行。
- 已有目标内容一致时复用，不覆盖不同版本。人工复用需明确核验并记录目标内容指纹；文件变化后必须重新核验。
- 复制使用单层独立暂存目录，完整内容校验通过后才发布。支持按文件取消；取消或失败后记录已复制文件，场景尚未执行。

## 预检与恢复

模型必须存放在接收库的子文件夹，库根不可分配或插入。SDK 始终接收最终模型包的真实绝对路径，保留原文件名；不创建插入中转联接、不切换库根或工作目录，不通过建模、另存为或修改 PSZ 完成常规插入。

非 ASCII 路径采用 AppFunc 兼容层，以 x64 PS `2402.14.0.1127` 的插入指令布局为基准，处理进程实际加载的 `AppFunc.dll`。DLL 产品版本资源（例如 `2402.1400`）仅用于日志，不参与兼容判定。仅在计划需要新插入非 ASCII 路径模型时只读检查兼容性，读取工程信息或传输焊点不触发此检查。兼容判定依据 A 点、文件访问判断上下文、B 点及其调用指令是否匹配，并确认这些指令位于当前模块的可执行范围；不要求安装目录、文件大小、镜像总大小、节表数量、导出数量、异常函数表数量或整份磁盘镜像一致。ASCII 路径正常调用 SDK，不启用此兼容层。

兼容层仅在插入调用范围内将 RVA `0x27DF43`（A 点）的六字节条件跳转临时置为空操作，以绕过已定位的路径访问误判；保留 RVA `0x280110`（B 点）的库同步检查。调用结束或抛出异常后均恢复 A 点原字节、页面保护并刷新指令缓存；恢复失败时禁止本进程继续插入，错误明确要求重启 PS。不会修改磁盘上的 AppFunc.dll。插件内的插入调用串行执行并拒绝重入；此锁不约束宿主或其他插件的原生线程。

SDK 插入组件时 `TxInsertComponentCreationData.Name` 留空，普通导入保留 SDK 从模型文档读取的显示名；场景对象名、源模型文件名、接收库存放路径分别处理。仅存在独立目标名称（`TargetName`）的同名导出根在插入后应用该名称。已有实例的空库存储引用仍阻断复用，提示说明这是存储状态问题，不要求场景对象名与 `.cojt` 文件名相同。

正式引用校验要求组件已结束建模、实际 `TxLibraryStorage.FullPath` 对应最终接收位置且模型文档存在，目录联接不作为正式库引用。不再自动尝试已失败的 `CopyToLocal → SaveToLibrary` 流程，不把结束建模当作路径重定位。SDK 抛出异常且场景已有新增对象时停止重试，并按实际新增实例计数，防止重复实例。

通过 `Paste` 重建原生树关系得到的实例属于新对象，SDK 不保证副本仍持有正式库引用。这类实例必须用 `VerifyPastedCojt` 重新核对模型文档与最终库路径；未通过核验的实例不能计为已归位，避免出现「树里层级正确、模型引用已丢」的情况。`InsertCojt` 保留 `allowRoot` 参数，供配方快速验证时直接插入库根；常规导入和插件界面始终要求 COJT 位于库内子文件夹。

已有同名实例引用其他位置、没有可读库引用或仍在建模时，预检显示实际引用和计划位置，停止复用，不自动迁移。需要改变已有实例的存放位置时，在接收端另存为到指定子文件夹，或核对并撤销失败导入后重新传输。场景显示名与模型文件名无需相同。

接收端其他对象的建模状态不构成全局传输阻断，也不会被预检或传输主动结束。预检问题按文件和存放分配、接收工程和重建分类，显示完整原因、处理方法及实际 SDK 错误。预检只验证可读状态与元数据，插入结果由执行阶段的实际 SDK 返回及库引用核验判定。

- 插入或复制的实例已属于目标父集合时不重复挂载。需要移动时使用 SDK 集合的 CanBeAdded / AddObject，并验证操作后的父集合。新建统计包含插入和复制的实例。
- RPC 适配器将工具失败包装进错误字段时，仅接受任务编号和计划指纹均匹配的结构化结果。明确的 failed 为终态，真实断连仍保留待确认状态。
- 已知失败可在核对或撤销已有变更后主动重新检查；使用新任务编号，不自动重发原任务。进入复制前再次只读确认接收工程与场景状态。

预检检查文件快照、源模型内容、XML 中可识别的模型与图片依赖、目标冲突、目录可写性、空间、父容器、位姿及焊点绑定。包外引用、缺失依赖、随目录迁移会失效的包内绝对引用会阻止新复制，需要重新包装为相对引用或核验复用已有目标。依赖检查不解析 JT/CGR 等二进制内部引用。

模型 TSV 包含源对象、源父对象和工程标识，支持资源/零件混合层级及源到目标对象 ID 映射。后续焊点可复用同源、同接收工程的成功模型映射；缺少映射的绑定需在接收端明确确认。旧 TSV 仍可读取，但不能推断缺失的工程身份。

模型 TSV 的 `WorldTransform` 保存每个实例完整的世界旋转矩阵和 XYZ 平移，避免欧拉角转换及小数截断；原六个位姿列仍保留并使用往返精度，兼容旧数据。源端通过 `ITxLocatableObject.AbsoluteLocation` 读取，失败时报错，不写入零位姿。接收端在全部插入、复制和挂载完成后按父先子后统一设置变换后的世界位姿。旧接口未提供双端坐标时保留原 XYZ 偏移语义。

人工焊点绑定限定在接收进程、工程名称、研究标识、工程文件和库根组成的身份范围内；任一变化清除旧绑定、对象映射和待处理拾取。刷新同一接收身份保留有效绑定。模型映射每次同步先清空，仅在成功模型任务的源端与接收身份完全匹配时恢复。问题项直接携带焊点 Key，与显示文案分离；修复按钮仅作用于选中的绑定问题。

执行前再次核验工程、场景摘要和目标文件；配置或场景变化会使预检失效。任务在场景修改前记录运行状态，同一任务标识及指纹不会重复执行。通信超时后查询任务状态，未知或运行中状态禁止重发。待确认记录保存在运行时 CrossEnvIO 目录，当前 PS 进程内重新打开窗口会恢复查询；进程崩溃留下的运行中任务需核对目标场景，不自动推断失败。

插入、层级和位姿修改使用场景撤销分组，撤销需在接收端操作。进入场景执行后始终保留模型依赖文件；文件清理仅处理未使用批次，并核验所有可发现实例的引用、目标实例在线状态及文件内容。清理不能代替场景撤销，也不能检查未打开工程的引用。

常规导入不保存或重载工程，未保存的接收工程也可预检；完成后由使用者保存工程。旧接口中显式请求的 PSZ 路径修复仍保留原编码和 BOM，不能表示的新路径会拒绝修改，不强制转换为 UTF-8。

焊点页支持直接选取焊点位置操作、关联的实体焊点或包含焊点的操作组。操作组按实际操作树展开，组合选取按操作 ID 去重；没有关联操作的焊点或不支持的对象会列出名称、实际类型与建议，不静默忽略。

焊点默认允许缺少接收绑定零件：仍传输位置和朝向，缺失或不唯一的自动绑定记录在日志及“未新增绑定”计数中，不因此判定整批失败，也不清除接收端已有绑定。JSON 数据损坏、失效的人工绑定、仅修改绑定或显式投影仍报告错误。勾选“同时传输本端绑定零件”时，从所选焊点汇总并去重源端零件，生成独立模型快照；先复制并重建零件，再用源到目标对象映射恢复焊点绑定。模型重建失败时停止，不继续创建焊点；模型和焊点共用接收端场景撤销分组。携带零件的离线传输使用 `.cxio`，包内同时保存焊点、绑定零件结构及唯一 cojt；独立 TSV 不携带模型包。

## 离线传输

- TSV：结构、名称、位姿、源关联及焊点绑定信息。
- `.cxio`：ZIP 格式的 TSV、清单及唯一模型包，按字节保留模型文件和空目录，导入时验证摘要。
- 解包拒绝路径穿越及重复文件，限制为 100000 条目、64 GB 总内容、8 MB 清单和 128 MB TSV，并检查临时空间。

结构 TSV 重建不传输设备关节状态、完整工艺属性或其他未序列化数据。插入后 SDK 类型不一致会报告失败，不冒充成功重建。

## 设备原型

模型 TSV 的 `PrototypeData` 列保存源端 Planning 原型类型、Family、重量、原 ExternalId 和 SDK 实际类型。原型优先从 SDK `TxTunePmDocumentManager.LoadPrototypeDataFromDocument` 读取，Planning 实例的只读 `Prototype` 用于补充原型类型。

TuneData 原型记录由 SDK 按当前工程 ID 读取，直接复制 cojt 不保证接收工程已有对应记录。预检检查源记录的 Type、Family 和重量，不调用接收端 `CreatePrototypeData` 查询类型元数据。执行时保留源 Type 和 Family，分配新的目标 ExternalID，用 `TxTunePmDocumentPrototypeData` 承载原记录并调用 `SavePrototypeDataToDocument` 写入当前接收工程。PS 2402 的数据对象构造器为 internal，按已知四参数签名封装反射调用；不通过工厂重新推断 Family 或替换原类型。写入前备份目标 TuneData，回读核对 Type、Family、重量及目标 ExternalID；已有目标记录需同时匹配 Type、Family 和重量才复用。写入失败恢复原始 TuneData 字节；成功后保留备份路径。仅支持离线工程。

`CreatePrototypeData` 的 `TxPlanningTypeDoesNotExistException` 同时可能表示类型元数据尚未加载或指定类型不在当前元数据中，不能直接判定 cojt 的原型记录无效。完整 TuneData 记录不依赖这次查询；仅在源端记录缺少 Family 且无法由明确的基础原型类恢复时，才在源端查询以补全记录。异常按发生阶段说明，不把元数据查询错误解释成文件缺失或未定义设备。

SDK 合法修改的目标包按工程身份、目标路径、源摘要、原型描述和完整目标摘要记录复用凭据；任一条件变化仍阻止复用。旧设备 TSV 缺少原型数据时要求重新从源端导出。Planning 原型不代替 cojt 内部的工具或机器人运动学定义；插入后仍须匹配源 SDK 类型，错误会记录预期类型、实际类型和 SDK 插入详情。

## 构建与接口

使用 `tools/Build.ps1`，输出到外部 `TxTools.Local/build`。回归与 WinForms 布局测试位于外部本地测试目录；布局回归纳入真实 `PluginUiPolicy`，SDK 控件替身模拟初始化时重新设定尺寸。本地用例涵盖兼容指纹拒绝、A 点作用范围和失败恢复、中文路径与原文件名、多实例复用、焊点选择展开、目录分配及独立窗口关闭；PSZ 工具另保留编码与恢复测试。替身用例不能代替实际宿主中的插入、保存重开、拾取、撤销和跨进程验收。

两端均需加载兼容版本，传输协议为 2，模型插入能力版本为 6（`guarded_appfunc_a`）。新增工具 `crossenv_transfer_check`、`crossenv_transfer_execute`、`crossenv_transfer_status` 和 `crossenv_pick_request/status`；检查和状态查询为只读工具。旧离线包可读取，缺少设备原型信息时预检阻止设备重建；旧 `crossenv_rebuild` 接口保持兼容。
