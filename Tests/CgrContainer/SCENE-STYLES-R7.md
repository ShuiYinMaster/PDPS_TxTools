# R7：变长公共头、属性继承、颜色/透明度和线样式

日期：2026-10-16。场景版本 `CGRSCENE-20261016-R7-variable-attributes`。全部应用操作通过 CATIA COM 完成，仅操作研究副本及自建文档，未部署 PS DLL。

## 修正：公共头不是固定 35 字节

R5/R6 的默认样本中，公共头首字段都是单字节 0，因而被当成了普通标志字节。独立装配实例设置颜色或透明度继承后，首字段变为 `FF + uint32LE`，公共头增长为 39 字节。旧解析器会错读随后节点属性及矩阵标志。

修正后的公共头顺序如下；几何、矩阵等边界由顺序读取决定，不再假定公共头固定长度。

| 字段 | 编码 | 本轮结论 |
| --- | --- | --- |
| 继承掩码 | compact：小于 255 为单字节，否则 FF + uint32LE | 颜色、透明度、线宽和线型的继承开关 |
| 节点状态 | byte | 保留 R6 的禁止拾取 0x01、95 体积贡献 0x10；本轮确认半透明 0x80 |
| 图形样式 | uint16LE | bits 4..9 为线宽码，bits 10..15 为线型码；低 4 位尚未完整解释 |
| 颜色源槽 | byte | 显式颜色样本为 FF；默认 FD 等其他值的完整含义待解 |
| 不透明度 | byte | 与 COM SetRealOpacity 的 0..255 数值对应 |
| 颜色槽 | B、G、R、尾字节 | 三通道顺序已确认，尾字节仍保留原值，不能解释整个槽的所有形式 |
| field11 | byte | 含义待解 |
| 球半径、scalar16、球心 XYZ | 5 × Float32LE | scalar16 含义仍待解 |
| 标识槽 | uint32LE | 完整分配规则待解 |

通常为 **35 字节**，扩展继承掩码时为 **39 字节**。Python 保留继承掩码原来的短/扩展形式，包括非最短的扩展零值；C# 按值选择标准紧凑形式。62/A3 的图层、选项、矩阵标志紧跟实际公共头，而不是固定记录偏移。

为保留已有探针接口，Python `flags` / `encoding` 元组仍保留历史名称：`flags[0]` 现在是继承掩码，不一定是 byte；`flags[2]` 和 `encoding[0]` 实际是同一个图形样式字的低、高字节。新增语义属性供读取，不能再把这两个元组直接拼成固定六字节头。

## COM 继承对照

每个案例新建 Product，包含同一研究 Part 的两个实例；第二实例平移 `(80,0,0)`。只修改第一实例，独立导出并关闭该 Product，避免累积样式。另测根 Product 颜色继承。

| COM 属性 | 继承参数 0 | 继承参数 1 |
| --- | ---: | ---: |
| SetRealColor(17,93,201,inherit) | 0 | 0x404 |
| SetRealOpacity(128,inherit) | 0 | 0x1000 |
| SetRealWidth(4,inherit) | 0 | 0x10 |
| SetRealLineType(3,inherit) | 0 | 0x40 |

相同属性值下，切换继承参数只改变对应掩码；颜色 0x404 是本轮观察到的**组合掩码**，尚未分离解释其中 0x004 与 0x400 的独立作用。

同时设置颜色 `(41,83,167)`、不透明度 73、线宽 16、线型 3，全部继承参数为 1，得到掩码 `0x1454 = 0x404 | 0x1000 | 0x10 | 0x40`，属性值均独立保留。单个局部继承位不等于整条装配路径最终显示属性，完整父子优先级仍需更多实验。

## 线宽与线型跨字节打包

单独设置线宽时，保持线型 1 和低标志 4：

| 请求线宽 | 原生图形样式字 | 解出的线宽码 |
| ---: | ---: | ---: |
| 1 | 0x0414 | 1 |
| 2 | 0x0424 | 2 |
| 15 | 0x04F4 | 15 |
| 16 | 0x0504 | 16 |
| 31 | 0x05F4 | 31 |
| 32 | 0x0604 | 32 |
| 47 | 0x06F4 | 47 |
| 55 | 0x0774 | 55 |

因此不能把原“category”字节的高半字节直接当完整线宽；高位跨到后一个字节。提取规则为 `(graphics_style >> 4) & 63`。线型 1、2、3、63 均符合 `graphics_style >> 10`，组合属性仍吻合。

本环境请求线宽 62、63 时导出码为 1，不是原值。本轮记录该回退现象，没有证明全部 COM 线宽索引的有效范围、配置映射或实际毫米宽度。

## 颜色与透明度

除 `(17,93,201)` 外，又分别设置 `(231,17,3)`、`(5,211,31)`、`(13,7,197)`，三通道均按 **BGR** 写入原属性槽的前三字节。默认颜色源 FD 的槽不能无条件视为显式 RGB；透明度操作也可能使颜色源槽变为 FF，最终可见颜色仍需结合继承路径解释。

不透明度另测 0、1、64、127、128、200、254、255，均按 byte 原值写出。0x80 状态位在小于 255 时置位、255 时清除，与继承参数是两个独立控制。这里的 0x10 继承掩码与 R6 的 95 状态字节 0x10 位属于不同字段，不能混用。

## 根球偏心位置的计算证据

对原点、正坐标、负坐标、XY 居中及小尺寸的五个新原生箱体，用叶球 `B(c,r)` 与原点零半径球合并：

- 若叶球已包含原点，根球保持叶球。
- 否则 `d=|c|`、`R=(d+r)/2`、`C=c*(R/d)`。

五个根球的中心和半径均吻合，最大分量误差小于 `2×10^-5`，解释了 R5 中根球偏离网格包围盒中心的现象。`scene_bounds.py` 保留通用两球合并计算供复核。

这只是当前单体原生箱体配置的算法证据，未证明所有场景都以原点球初始化，也未推定任意多子节点的合并顺序或数值舍入。生产编码器的球策略本轮没有改动。根 `scalar16` 在这些不同坐标箱体中仍为 11，不能据此将它命名为 minX 等几何坐标。
