# TxAgent — Process Simulate AI Agent / 进程内 AI 助手

An in-process AI assistant for Tecnomatix Process Simulate, with scene tools, reusable C# / Python recipes and multi-instance collaboration.

## 配方分享与待固化片段

展开聊天区右侧的配方栏，在已有配方卡片内点击“导出”，即可保存可分享的 `.md` 文件。接收者点击配方栏顶部“导入”并选择文件；同名配方另存为带“导入”序号的新副本，不覆盖原配方。导入会校验参数和代码格式，只保存定义，执行前需重新选取当前工程的对象。

配方栏分为“我的配方（数量）”和“待固化（数量）”两个页签，默认显示“我的配方”。已固化配方使用蓝绿色状态标签和实线卡片；待固化片段使用橙色“待整理”标签、浅色背景和虚线卡片。切换页签会保留已填写的参数和对象绑定。

待固化片段优先显示用途说明中的可读能力名称，原始片段名放在副标题中，并显示中文能力标签、脚本语言和成功/失败次数；“代码预览”可展开查看，“详情”将完整说明和代码显示到对话中。“整理为配方”会预填整理指令，发送后由 AI 生成带中文说明和参数标签的配方。配方栏的说明和对话中的配方文档均渲染 Markdown；已有配方的 `⟨⟩` 按钮可在对话中查看完整文档。

## 架构一览

TxAgent 在 Process Simulate 2402 中提供聊天、工具调用、代码片段、配方和多实例协作。入口是 `TxAgentCommand.cs`，详细项目环境见 [总 README](../README.md)，版本变化见 [更新日志](../CHANGELOG.md)。

## 环境与启动

聊天界面已拆为共享 `UserControl`，支持由 PS 可停靠 Viewer 承载。目标机器注册
`TxAgentDockViewer` 后，原 TxAgent 命令自动使用停靠面板；未注册时继续使用独立窗口。
注册参数、当前验证范围及目标机器验收步骤见 [停靠 Viewer 部署说明](deployment/DockingViewer.md)。

- 主插件为 .NET Framework 4.8 / x64；`TxTools.csproj` 当前设置 `LangVersion=8.0`，PS 脚本与配方中的 C# 保持 C# 7.3 兼容。
- 聊天和配方界面使用 WebView2；模型请求由 C# 客户端发出。桌面宠物使用独立 Electron 进程，不在 PS 内解码动画。
- 注册 `TxAgent` 命令并打开窗口，在界面配置提供商、模型和 API Key。源码提供 DeepSeek、Kimi、千问、OpenAI、Ollama 及自定义 OpenAI 兼容提供商；具体可用模型取决于端点配置。
- Key 按提供商分别存入 `{providerId}.key`，由 Windows DPAPI 绑定当前用户加密。优先使用插件目录，不可写时回退到 `%LOCALAPPDATA%\TxTools.Agent`；更换用户或机器后需重新配置。

## 使用流程

### 执行过程与补充引导

流式回复默认跟随最新内容。向上滚动会暂停跟随，点击“回到最新”或滚回底部后恢复；
展开的思考区域也保留独立的滚动位置。执行过程收纳思考、阶段说明和工具记录，
结束后默认折叠，结论保持可见；失败、未完成和未执行的数量保留在过程摘要中。

回复底部提供“复制结论”和“复制本轮”，保留 Markdown 原文与代码格式。
“更多”菜单中的“复制完整对话”复制整段会话及工具记录，不包含思考内容。

执行期间输入框可提交文字补充引导。引导按顺序进入当前任务的后续上下文，
在模型返回后或工具之间的安全边界应用，不强行中断已经开始的工具。
新要求到达时，尚未开始的旧计划调用标记为未执行，随后重新规划。
界面区分排队、已应用和未应用状态；未应用的内容可恢复到输入框。
执行中的引导暂不接收附件，切换模型、会话或撤销历史需先停止当前执行。

### 常用步骤

1. 先通过场景查询、搜索和操作列表读取真实工程数据。
2. 工程变更前检查工具参数或代码审批；支持撤销的操作完成后可在 PS 中回退。
3. 复杂任务可建立计划，将验证过的 C# 或 Python 代码保存为带参数的配方。
4. 在侧栏或快捷配方窗口选取当前研究的对象、填写参数并执行，不需要再次调用模型。

## 配方格式与控件

配方以 Markdown 保存完整代码、参数及可选执行按钮，读取和写入由 `Core/RecipeStore.cs` 负责。旧 `recipes.json` 不等同于当前可执行 Markdown 配方。

- 参数变量名为英文标识，界面标题和说明可用中文。类型支持 `object`、`objects`、`number`、`text`、`bool`、`color`。
- 文本和数字可通过 `choices` 提供下拉选项；颜色使用色盘和常用色块，值为 `#RRGGBB`。
- 对象参数启用 `objectFilter` 后可按类型和名称关键词取当前选择或查找当前研究。更改条件或研究会清除旧绑定；对象 ID 不写入默认值、按钮参数或标量偏好。
- `actions` 为同一份代码定义多个执行按钮，`args` 覆盖标量参数。模型调用时通过 `__recipe_action` 选择按钮；执行端重新校验参数及按钮覆盖值。
- 侧栏与快捷窗口均支持参数记忆和恢复默认值。所有按钮都已覆盖的参数可隐藏输入框；没有按钮声明的旧配方继续显示单个执行按钮。
- `save_recipe` 从片段固化时传 `source_snippet`，更新时传 `id`，保留配方身份、来源和运行记录；导入导出同时保留参数选项和按钮定义。

按钮示例（用于配方的执行按钮 JSON 数组）：

```json
[
  {"id":"show","label":"显示","args":{"show_objects":"true"}},
  {"id":"hide","label":"隐藏","args":{"show_objects":"false"}}
]
```

默认配方覆盖显示/隐藏、原点/几何中心坐标、常用色与自定义色、对象编号，以及从标记几何生成焊点。升级仅替换与旧内置定义完全匹配的文件，先备份并保留运行记录；用户修改或删除的默认配方不会强行恢复。

## 启动与对象类型

命令注册阶段设置 5 秒延后定时器及退出事件。主窗口出现且消息循环可处理定时消息后，捕获 PS 主线程上下文，在后台读取配方、注册工具和启动实例服务。桌面宠物的文件检查和进程启动也放在后台；所有 SDK 调用及界面回调仍回到 PS 主线程。

对象类别在对象参数展开时从当前场景读取，按参数类型过滤；“刷新类型”同步新增和删除的类别。收起的侧栏与快捷窗口列表页不扫描场景。中文类型映射维护于 `RecipeUiActions`，标签重名时显示原始类型名，未知类别保留 SDK 名称。

`audit.log` 的 `[Startup]` 记录是后台初始化耗时，不是 PS 完整启动时间。

## 桌面宠物组件

同一 Windows 桌面会话共用一只鲸鱼娘。先把目标 Process Simulate 窗口切到前台，再点击鲸鱼娘打开快捷配方；菜单获得焦点时沿用点击前的目标。快捷配方的对象选择、条件查询和执行均在该进程内完成。切换前台会收起旧面板并清除对象绑定；排队执行的配方在修改场景前再次确认前台和研究。

Agent GUI 的桌宠开关控制共享显示状态并记忆隐藏。宿主进程退出后，剩余插件进程自动接管；最后一个进程关闭时桌宠退出。更新需要同时复制新版 DLL/PDB 和 `Agent/UI/pet/dsh-pet` 目录，并重启所有 PS 进程。实现与验证记录见 [共享桌宠说明](maintenance/SharedDesktopPet.md)。

源码包含适配脚本；Electron 与动画素材按需恢复，不提交下载的运行组件。安装、固定版本和校验方法见 [桌宠组件说明](maintenance/DesktopPetComponents.md)。

```powershell
pwsh -File Agent/maintenance/Install-DshPetComponents.ps1
node Agent/UI/pet/dsh-pet-tools/validate.cjs
```

## 线程、审批与执行

`PsContext` / `PsAgentHost` 负责将 SDK 调用封送回 PS 主线程，工具内不得另起线程直接访问工程对象。模型调用按工具只读/变更属性进入审批和审计；界面直接运行配方使用既有撤销块与共享执行锁。可撤销性取决于具体工具，不应假定 Python、文件或外部系统写入都能由 PS 撤销。

## 撤销与恢复（2026-10-07）

C#、Python 及相关工程写工具使用场景撤销分组；开启失败阻止写入，关闭失败报告错误。执行失败不代表自动回滚。独立模式恢复点为已导出并校验的工程快照，外部文件和应用写入需另行恢复。

详见 [统一撤销与恢复说明](../docs/undo-safety.md)。

### 插件工具接口

| 工具 | 参数与行为 |
| --- | --- |
| `check_reachability` | 复用可达性插件的多 TCP、IK、限位、奇异与临界分析；`tcp_check` 和 `interference` 可启用额外检查。`operation` 名称匹配必须唯一，也可传 `object_id`。检查期间临时切换姿态和 TCPF，结束后恢复；返回完整汇总、有限点位明细与干涉三态结果。 |
| `check_robot_base` | 复用 BASE0 分析，分别统计一致、偏差、无 BASE0 和无法对比。默认位置容差 0.5mm、旋转容差 0.01，旋转值沿用插件的 PS RPY 原生单位。可用 `name` 或 `object_id` 限定机器人。 |
| `correct_robot_base` | 重新检查后同步偏差项并复查；需变更审批，使用场景撤销分组。缺少 BASE0 或无法对比的对象跳过。部分失败不自动回滚。 |
| `export_weld_screenshots` | 视图工具组中提供。将当前视口截图、可编辑分类形状、文字、引线及可选世界坐标表写入活动 Excel 工作簿。支持操作 ID、标注命名模式和板厚分类；需先打开 Excel 并设置当前视角。写入需审批，不自动保存工作簿。 |

可达性明细默认每个操作最多返回 100 项，异常点优先；汇总统计始终包含全部已检查点。`collision_not_checked` 和 `collision_unknown` 均不代表无干涉。
### 设备网格调平与落地

`scan_devices_z` 与 `align_devices_z` 共用世界坐标三角网格测量。读取复用实体级加载、外观实例映射和三角带解析，直接使用双精度顶点，不通过导出文件或单精度缓存，也不使用资源原点作为最低点兜底。读取结束后恢复显示及表示级别；建模状态或无法恢复的表示级别会阻止读取。

扫描默认 `scope=scene`；使用 `scope=selected` 扫描当前选择，或用 `object_ids` 精确指定整台资源。校正默认只处理当前选择，支持相同的 `object_ids`，不允许直接校正全场景。父子重叠目标只处理上层资源，机器人、末端工具及外部设备附着关系受到保护。

默认 `level=true`：根据底部三角面的下包络、面积加权法向、空间覆盖和共面误差判断支撑基准，保持资源 X 轴的水平投影朝向，围绕支撑中心整体调平，然后使完整网格最低点到达 `target_z_mm`。法向不一致、支脚不共面、覆盖不足或有几何低于支撑面时返回 `blocked`。可用扫描返回的 `support_geometry_ids` 指定支撑几何；仍会检查完整网格的最低点。明确设置 `level=false` 时只按网格最低点做世界 Z 平移。

| 参数 | 默认值 | 单位/含义 |
| --- | --- | --- |
| `target_z_mm` | 0 | 世界坐标目标高度 |
| `position_tolerance_mm` | 0.1 | 最低点高度容差 |
| `angle_tolerance_deg` | 0.05 | 调平及支撑法向一致性容差 |
| `plane_tolerance_mm` | 0.5 | 支撑共面误差容差 |
| `max_tilt_deg` | 3 | 接近摆正状态下的最大候选倾角，上限 10° |
| `max_triangles` | 1000000 | 完整读取上限；超限报错，不使用截断网格 |

调用示例：

`scan_devices_z({"scope":"selected"})`

`align_devices_z({"object_ids":["资源场景ID"],"level":true,"target_z_mm":0})`

输出包含实际网格最低点、支撑几何 ID、支撑面倾角、世界 X/Y 方向高差、共面误差以及校正计划。资源发生旋转时，X/Y 方向高差是世界轴方向，不代表资源的前后左右。`aligned` 只在写入后重新读取网格及位姿复查通过时返回；`verification_failed` 表示场景可能已变更，需检查结果或在当前 PS 工程 Ctrl+Z。实体重载在位姿撤销事务之外进行，位姿修改使用一个撤销分组，部分失败不自动回滚。

最低点与支撑分析针对当前模型的三角化表示，精度受模型表示影响。底部候选识别采用保守规则，复杂底座可能需要明确支撑几何。它不修改各支脚的几何或装配尺寸。
